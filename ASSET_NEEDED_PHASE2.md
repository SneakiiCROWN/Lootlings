## Authority, priority and delivery rules

- **REQUIRED NOW** = visible live weakness or existing roster art gate suitable for the next focused art delivery. It does not enable characters or change rewards automatically. **LATER** = already-defined content or optional polish dependent on an explicit implementation milestone. **REFERENCE ONLY** = approved inspiration without a current content contract; do not commission/implement automatically.
- Canonical sheets in `art/reference/canonical/characters/` override broader board creature designs. Keep the neutral Relic Beast face, amber eyes, ears, horns, beige/cream fur, curled tail, gear, satchel and Core exactly. Emberhorn is separate. Crystal-cat/Pixie imagery is not a redesign instruction.
- Cute + badass + dark fantasy + treasure hunting. Existing gold/purple/cyan UI remains premium painted fantasy. Adult human/humanoid glamour is permitted only for explicitly adult designs with agency/personality; never apply adult outfit proportions to tiny canonical Lootlings.
- PNG sRGB, clean straight alpha, no baked text/numbers, no sheet labels/background debris. Source/layer files and provenance accompany delivery. Owner-supplied reference approval does not establish an external licence. New sourced art needs author, direct source, exact commercial licence/permission and attribution record.
- Actor cutouts need complete silhouette, 5–8% transparent safety padding and consistent contact/hand/Core anchors. Ready/attack frames must fit the same canvas. Weapons separate from body; keep grip and projectile sockets recorded. Validate actors at ~110–208px and item icons at 44–120px, not only at source size.
- Motion/state names below are requested exports, not new combat rules. Existing timing/RNG/saves/drop odds are immutable for an art integration. No full skeleton/huge animation pipeline is required. Texture integration must be bounded and tested at 480×854.
- Exact paths below are proposed delivery destinations; most new paths do not yet have a loader. A named data field is NOT proof of a working renderer. Hooks explicitly identify missing wiring. No blind reference-board crops.
- Deduplication: one base icon serves all rarity/affix variants; one Signature mark serves every compatible item; one weapon export may serve both card and held art; one Scraprat sprite may serve all pack members. Evolution strips describe 108 designed stages in 36 files, not 108 separate commissions. Optional portraits should reuse accepted idle cutouts until separate composition is actually needed.

## Remaining temporary visuals and boundaries

Live Home residents/critter/chest-twitch prop remain geometric; request residents above, reuse accepted chest export for twitch rather than another unique asset. Ranger arrows/Mage orbs, coin/XP pickups, loot beams, proc/death/impact rings and tiny ambient particles remain code-drawn. Some of these are intentionally cheap supporting effects, not universally defective. Thin outlines, shadows, motes, fades, squash and text outlines are presentation code, not permanent substitute character artwork. Uncalled `draw_lootling_procedural` / `draw_enemy_procedural` functions are legacy fallback code, not the current actor appearance; no new assets required for them.

The Hoard Dragon is a real painted runtime texture, not a purple blob, but existing ART_BLOCKER notes and human feedback still call for anatomy/quality replacement. The inspected source has a large coherent-looking outline; that does not supersede the recorded quality blocker or justify shipping a random demon-sheet crop. Art approval must inspect the actual 208×174 phone footprint, limbs/contact and motion before accepting a replacement.

Relic/Scavenged reward rules/data exist but physical closed→open art/sequence hooks are not equivalent to Hoard's live renderer. Results, item decisions, shop prices, rarity names, Trophy concealment and locked character availability stay unchanged. No broad Phase 2 gameplay implementation occurs in this audit.

Use existing particle/node/audio limits and texture caching. Verify parser/import, isolated save/inventory/economy regression, unchanged seeded balance and real OpenGL screens before runtime integration. This audit itself changes only references/docs; no new asset is loaded by gameplay.
