# Phase 3 frozen baseline

Gameplay checkpoint: `3bbd66c`; Godot `4.7.2.stable.official.ed1daf0bf`. No gameplay/economy values were changed before these measurements. `baseline/runs.jsonl` contains 512 individual results; six additional fresh-scene comparisons assert identical replays. Every sample clears fixture saves before scene construction, resets inventory/meta/campaign/avatar and seeds global/combat/loot/visual RNG before `start_run` spawns. Player saves are inaccessible through the guarded runner.

Coverage: 12 weapon families × four Core policies × eight shared seeds; ten campaigns × eight sustain-policy seeds; twelve actors × two input policies × two seeds. Actor cosmetics have equal baseline mechanics. Two seeds per actor is characterization, not adequate evidence of final character parity. Policies retain starting weapons, equip same-or-better rarity non-weapons, and buy at most two cheapest affordable non-weapon offers. This deliberately limited bot cannot establish real player win rates or subjective combat quality. It can leave affordable weapons unbought. Decision menus consume no fictitious combat time. Foe TTK includes approach/entry and real process/hit-stop time; effective DPS = original foe HP / elapsed fight, not raw damage or overkill. Failed unfinished fights are excluded from completed-fight duration; run outcome is retained. Burst and sustained raw DPS are separately measured against a large stationary target in `dps.log`.

Findings: greatsword Physical 7/8 completions, Fire 4/8, Lightning 7/8, Poison 8/8. Completed Hoard fights range 6.25–22.8 seconds across those policies. This does not justify forcing a success quota. Baseline neutral four-taps/second sustained weapon DPS spans 49.19–70.38; heavy weapons compensate melee approach with higher hit power and armour, sling control trades speed for survival, orb sustain adds value beyond DPS. Regular loot sample: 695/10,000 drops, Common 503/Rare 150/Epic 34/Legendary 8; longest drought 102 rolls, 17 successive duplicate item IDs. Scrap cache expected salvage 4.1 against cost 20; persistent buy/salvage prices all lose currency, preserving sinks. Full distributions and per-wave income/spending are retained alongside weak-to-strong sample ordering.

Reproduced code defects: `spawn_single_enemy` does not clear `enemy_weapon_opening_used`, although group/debug spawning does; spear's advertised per-foe opening becomes once per run. Lifesteal uses uncapped attack amount after subtracting HP, so overkill can restore health that was never dealt. Training purchases can exceed the persisted rank-100 cap. Text calls Static Fingers +80% damage although it adds 80 percentage points of base-hit power, and Quick Grip 18% faster although it shortens the interval 18%. These need honest contracts rather than arbitrary global damage buffs.

Corrections proposed before implementation: reset target-bound openings; leech only HP removed; enforce the existing training cap; clarify effect text; limit damaging control accumulation before adding new stagger perks; preserve baseline raw family cadence/HP curves while introducing explicit character tradeoffs, learnable boss action loops/recovery, weighted compatible elites, two optional safe-boundary events, curated behaviour loot, boss-source weighting, merchant identity and bounded equipment drought protection. Re-measure the same seeds and inspect native phone/tablet output. Keep/revert based on outcome distributions, readability and transaction safety, not a win quota.

Fact checks: [Godot RandomNumberGenerator reference](https://docs.godotengine.org/en/stable/classes/class_randomnumbergenerator.html) confirms seed-based sequences but warns that the algorithm is an implementation detail and similar seeds can correlate; sample stream seeds use stable string hashes and engine version is pinned. Cross-version determinism is not promised. [Dan Hart's GDC economy case study](https://media.gdcvault.com/gdconline11/Dan_Hart_VirtualItemsSummit_BalancingYourGame.pdf), p28, motivates enumerating sources/sinks and distinct player activity models. We use that measurement method; no freemium values, monetisation rules or another game's tuning are adopted.

Run via `tools/run_qa.py --only phase3_balance phase3_dps phase3_economy`. `tools/phase3_report.py LOG --label LABEL` preserves JSONL and percentile distributions. Native inspection and real S23 feel/performance remain separate evidence gates. This file is a baseline checkpoint, not a completion sign-off.
